# Отчёт по улучшению API

## Текущий уровень зрелости: M1 (Resource-based)

### Проблемы

1. **Названия endpoint'ы**
   - `/add-room` — глагол в URL
   - `/room` — должно быть во множественном числе

2. **Названия параметров**
   - `guestsNum` — неясное название
   - camelCase в URL (лучше snake_case)

3. **Отсутствуют**
   - GET для получения одного ресурса
   - DELETE для отмены бронирования
   - Версионирование API

## Предложенные изменения

### 1. RESTful URL

| Старое | Новое | Обоснование |
|--------|-------|-------------|
| POST /add-room | POST /api/v1/rooms | Ресурс, не действие |
| GET /room | GET /api/v1/rooms | Множественное число |
| POST /booking | POST /api/v1/bookings | Множественное число |

### 2. Названия полей

| Старое | Новое | Обоснование |
|--------|-------|-------------|
| guestNum | max_guests | Понятнее |
| beds | beds_count | Явно указано, что это количество |
| bookingDates.checkIn | check_in | Упрощение структуры |

### 3. Новые endpoint'ы

- `GET /api/v1/rooms/{id}` — получить номер
- `GET /api/v1/bookings/{id}` — получить бронирование
- `DELETE /api/v1/bookings/{id}` — отменить бронирование

### 4. HTTP-статусы

- POST теперь возвращает 201 Created (вместо 200)
- 404 Not Found, если ресурс не найден

## Итоговый уровень зрелости: M2 (HTTP verbs)
