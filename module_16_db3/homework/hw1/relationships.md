# Классификация связей между таблицами

## 1. Actors и movie_cast

Связь: один ко многим — `1:N`.

Один актёр может участвовать во многих фильмах. Каждая запись в таблице `movie_cast` относится к одному актёру.

```text
actors.act_id → movie_cast.act_id
```

## 2. Movie и movie_cast

Связь: один ко многим — `1:N`.

Один фильм может иметь много актёров. Каждая запись в таблице `movie_cast` относится к одному фильму.

```text
movie.mov_id → movie_cast.mov_id
```

## 3. Actors и movie

Связь: многие ко многим — `M:N`.

Один актёр может сниматься во многих фильмах, а один фильм может включать много актёров.

Связь реализована через промежуточную таблицу `movie_cast`.

```text
actors → movie_cast ← movie
```

## 4. Movie и oscar_awarded

Связь: один ко многим — `1:N`.

Один фильм может иметь несколько записей о наградах. Каждая награда относится к одному фильму.

```text
movie.mov_id → oscar_awarded.mov_id
```

## 5. Director и movie

Связь: многие ко многим — `M:N`.

Один режиссёр может снять много фильмов, а один фильм может иметь нескольких режиссёров.

Связь реализована через промежуточную таблицу `movie_direction`.

```text
director → movie_direction ← movie
```

## 6. Director и movie_direction

Связь: один ко многим — `1:N`.

Один режиссёр может иметь много записей в таблице `movie_direction`.

```text
director.dir_id → movie_direction.dir_id
```

## 7. Movie и movie_direction

Связь: один ко многим — `1:N`.

Один фильм может иметь несколько записей в таблице `movie_direction`.

```text
movie.mov_id → movie_direction.mov_id
```

## Поведение при удалении

Для внешних ключей используется:

```sql
ON DELETE CASCADE
```

Если удалить актёра, его записи в `movie_cast` удалятся автоматически.

Если удалить фильм, удалятся связанные записи из `movie_cast`, `movie_direction` и `oscar_awarded`.

Если удалить режиссёра, удалятся связанные записи из `movie_direction`.

Такой вариант подходит, потому что записи в таблицах-связках не имеют смысла без соответствующего актёра, фильма или режиссёра.
